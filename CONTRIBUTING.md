# Contributing to regex-charclass

Bug reports, questions and pull requests are all welcome.

## Reporting a bug

Open an issue with the smallest set that reproduces the problem, the method you called, what you expected and what you got. `to_regex` is usually the shortest way to describe a set, and the `RangeSet` it is built on implements `Display` and `Debug`.

If the problem is a generated class that an engine rejects or reads differently, please say which engine and which Unicode version it carries.

## Before opening a pull request

Run what CI runs:

```sh
cargo fmt --check
cargo clippy --all-features --all-targets -- -D warnings
cargo test --all-targets
cargo test --all-features --all-targets
cargo test --all-features --doc
```

Please also:

- **Add a test.** Unit tests live next to the code; tests that drive the crate the way a dependent would live in `tests/`. `tests/regex_roundtrip.rs` is the one to extend when the change touches `to_regex`.
- **Document new public items.** `missing_docs` is warned on, and doc examples are run as tests, so an example in a doc comment is a test too.
- **Mind the README.** Its `rust` block is compiled and run as a doctest, through a `#[cfg(doctest)]` item in `src/lib.rs`, so an edit to it that does not compile fails CI like any other test.
- **Keep the MSRV.** The crate builds with Rust 1.63 and later, verified in CI. Raising it is a breaking change.
- **Update `CHANGELOG.md`** under an `## [Unreleased]` heading.

## What `to_regex` guarantees

The output has to be read back by a regular expression engine as exactly the same set of `char`. `tests/regex_roundtrip.rs` checks that with the `regex` crate: every ASCII `char` on its own, every pair of them, every escaped `char`, and a few hundred random sets are compiled and asked about the `char` values around each of their bounds.

Two forms are exempt from the membership check, and a change should not add a third. `\p{Name}` and the Perl classes name Unicode sets, whose contents depend on the engine's own UCD version, and `[]` is a placeholder for the empty set rather than a pattern, since an empty bracketed class does not parse.

## The surrogate block

`char` is not contiguous, and `RangeSet` needs a contiguous element type: it steps from one value to the next to decide whether two ranges touch. `Char` therefore counts by *index* rather than by codepoint and skips `U+D800..=U+DFFF`, so `'\u{D7FF}'` and `'\u{E000}'` are adjacent and the total set is one range.

Anything that does arithmetic on a `Char` has to work in that index space, `Char::index` and `Char::from_index`, and not on raw codepoints. `Add` and `Sub` used to disagree about this.

None of the methods here may panic on a malformed set, even though every constructor produces a well-formed one: `RangeSet` keeps its bounds in a public field, which can be written to directly. Iterate the bounds with `chunks_exact(2)` rather than by index.

## The Unicode tables

`src/tokens/unicode/` is generated by [`ucd-generate`](https://github.com/BurntSushi/ucd-generate) and is not edited by hand. `generate-classes.sh` has the commands and the UCD download they need. Those files are exempt from `rustfmt` and from `clippy`, so a regeneration is a readable diff rather than the whole table.

## Benchmarks

`cargo bench` measures `to_regex` on a set that resolves to a named class, on one that does not, and on a single `char`. Numbers move a lot with machine load, so compare runs on an otherwise idle machine before claiming a change is faster.

## Releasing

Publishing is automated. Push a `v*` tag matching the version in `Cargo.toml` and the release workflow checks formatting, clippy, tests, docs and a dry-run publish before it uploads to crates.io.
